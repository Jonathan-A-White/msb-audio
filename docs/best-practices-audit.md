# msb-audio best-practices audit

Audited 2026-10-10 at base commit 22478c5 (main, version 1.0.1). A docs-only story (mw-vtjxh4.33): no source file was changed. It marks the app against the factory's PWA best practices (`checklist.md`, one row per line, plus the rules added 2026-10-09 in the guide's changelog) and, for shared code, the library best practices chapter 01. The module boundaries themselves are already mapped in [module-map.md](module-map.md); this audit points to it rather than repeating it.

Checklist lines: 31

How to read it: **pass** means the rule is met and the evidence shows it; **fail** means it is not met (a fail row names the smallest fix and its size: XS is a few lines in one file, S is one file plus a test, M is several files and a test, L would be more than one story); **n/a** means the rule does not apply to this app and the evidence says why. A file:line in backticks was checked to exist by `bash docs/check-best-practices-audit.sh` (run it from the repo root; it also checks the row counts, the statuses, that every fail has a fix and size, and that the ranked list has at most 10 items each with a check). Commands quoted in evidence were run on 2026-10-10.

What the app is: a PWA download manager for Majority Standard Bible audio (66 books), Android Chrome only (`spec-3.md:8`, `spec-3.md:346`). It has one screen, no router, no text input, no speech, no pictures, no server and no database; its state is a status map in localStorage and the chosen folder handle in IndexedDB through idb-keyval. It is a PWA, so every PWA row applies unless the row says why not. There is no Android app or Python server in this repo.

Totals (31 checklist rows): 4 pass, 17 fail, 10 n/a. The six rule rows: 1 pass, 2 fail, 3 n/a.
